# Pose explorer — requirements and acceptance criteria

Status: proposed · 24 October 2026 · Companion to [pose-explorer-design.md](pose-explorer-design.md) and [ADR-0001 to ADR-0007](../adr/). Section I (slice S6) was added by ADR-0007.

This specification covers the spatial study panel ("Spatial study") on the explorer page. It replaces the single file `assets/viewer.js` with ES modules under `assets/explorer/`, then adds camera presets, joint inspection, provenance labelling, failure handling and reviewed pose estimates.

## Conventions

- **ID**: `PE-nn`. IDs are stable. Withdrawn criteria keep their number and are marked withdrawn.
- **Slice**: the delivery slice the criterion belongs to (see design §9). **S1** is the behaviour-preserving refactor. A criterion tagged S1 describes today's behaviour and must pass before and after the refactor. Criteria tagged S2–S6 are new behaviour and are expected to fail until their slice lands.
- **Method**:
  - **node**: `node --test tests/` against pure modules, fixtures and repository files, with no browser and no network.
  - **browser**: the `browser-gpu` MCP (`navigate_page`, `evaluate_script`, `list_console_messages`, `list_network_requests`, `resize_page`, `take_screenshot`) against `python -m http.server` serving the repository root.
  - **manual**: a person checks it and records the result in the pull request.
- **Test hook**: browser checks read `window.__explorer`, which exists only when the page URL carries `?explorer-test=1`. See design §6. Production URLs never expose it (PE-37).
- **Base URL**: in the steps below, `BASE` means `http://localhost:8080/?explorer-test=1`.
- **Angles** are in degrees and **distances** in metres. Quaternion comparisons use `|dot(a,b)| ≥ 1 − 1e-9`, which treats `q` and `−q` as equal. Position comparisons use a tolerance of 1e-4 unless stated.

## Hard constraints (from DESIGN.md, README.md and the model and DPMesh notes)

C1 colours only via CSS tokens · C2 44 px minimum targets · C3 no auto-rotation, respect reduced motion · C4 a keyboard alternative to every drag · C5 never imply the neutral rig demonstrates the selected movement · C6 no runtime GPU or ML dependency · C7 estimates visibly labelled as estimates, never as measurements · C8 no CDN, everything vendored · C9 works without WebGL · C10 no frontend build or bundler · C11 UK English.

## I. Sequence transitions (slice S6)

Transitions animate the avatar between **reviewed** estimates as the user moves through the form. The frames in between are synthetic. They are labelled as interpolated and never stored (ADR-0007). Terms used below:

- **Sequence**: the catalogue entries of `assets/catalogue.json` in ascending `ordinal`. A **sequence index** is a position in that order. Ids are not contiguous (0–103 across 103 entries), so adjacency is never computed as `id ± 1`.
- **Route source**: the `source` of the target's `yang:image-shown` event (design §7). Only `yang` and `chen` can have estimates.
- **Keyframe image** of an entry: the image `site.js` would display there after a navigation with that source selected, which is the first element of the entry's `images` whose `source` equals the route source (image index 0). The image id is that element's `file` without `.png`. An entry with no image of the route source has no keyframe image.
- **Reviewed estimate**: an image id listed in `assets/pose-estimates/index.json` whose file passes `validatePose(…, {origin:'published'})` and `checkLeftRight` (PE-30, PE-33). Nothing else counts as reviewed.
- **Estimate mode**: `'follow'` after the user activates `#apply-estimate` (PE-36) and its estimate is applied. It returns to `'off'` after clear, reset, a context failure or a switch to the fallback rig. It starts `'off'` on every page load and is never persisted.
- **Hop**: the motion between two consecutive keyframes of a route. `N` is the number of hops.
- **Navigation**: a `yang:image-shown` event whose `moveId` differs from the previous event's. It comes from `#previous`, `#next`, a position-list link or a `#move=` hash change. An event with the same `moveId` and a different `imageId` is an **image change**, from a thumbnail or source button.

The result is an internal pose, not a pose file, and has no provenance fields. | Node: endpoints within the Conventions tolerances (quaternion `|dot| ≥ 1 − 1e-9`, position 1e-4); for a 90° rotation about +Y on one joint, `t = 0.5` is 45° about +Y; `a = q`, `b = −q` gives `q` at every `t`; a joint only in `b` moves from identity; translation midpoint is exact; output keys are only `{joints, root}`. Applying `interpolatePose` and then `applyPose` matches slerping the local quaternions `L` to 1e-9 (conjugation preserves the slerp path). | node |
| PE-47 | Timing. Two named constants in `transition.js`: `HOP_MS = 1600` (one adjacent hop, slow and deliberate) and `CAP_MS = 3000` (the total for any route). With `N` hops, each hop takes `min(HOP_MS, CAP_MS / N)` and the total is `T = min(HOP_MS·N, CAP_MS)`. An adjacent move therefore takes 1.6 s, a 2-hop move 3 s (1.5 s per hop), and a 20-hop move 3 s (150 ms per keyframe). Both constants are in the test-hook snapshot as `transition.hopMs` and `transition.capMs` (PE-58), so tests read them rather than repeat them. Easing applies once across the whole route, not per hop: `p = easeInOutCubic(elapsed / T)`, with `easeInOutCubic(x) = x < 0.5 ? 4x³ : 1 − (−2x + 2)³ / 2`. Keyframe `k` (1-based) is reached exactly when `p = k/N`, and the figure does not stop at intermediate keyframes. Fetching (PE-55) happens before the clock starts and does not count towards `T`. | Node, driver on a fake clock: `routeTiming(1)` gives `{total: 1600, perHop: 1600}`, `(2)` gives `{3000, 1500}`, `(20)` gives `{3000, 150}` and `(30)` gives `{3000, 100}`; `hopIndex` takes every value `0…N−1` in order for `N = 5` at 60 Hz steps; at `elapsed = T/2`, `p = 0.5`. Browser, adjacent hop: from the first frame with `transition.progress > 0` to the first frame after arrival is `transition.hopMs` ± 50 ms, and a 20-hop jump takes `transition.capMs` ± 50 ms. The clock starts after fetching, so `transition.active` with `progress === 0` is excluded. | node + browser |
| PE-48 | Sub-sampling. If the route has more than `MAX_KEYFRAMES = 30` keyframes (a mean hop under 100 ms at the 3 s cap; with global easing the fastest hops are then about 67 ms, or 4 frames at 60 Hz), `planRoute` keeps 30 of them, evenly spaced by position in the route (`round(i·M/30)` for `i = 1…30`, with `M` the full count, so the target is always kept), and reports `skipped = M − 30`. The provenance detail says so (PE-50). With 30 or fewer, none is skipped. The constant is in the snapshot as `transition.maxKeyframes`. | Node: `M = 30` gives `skipped 0`; `M = 31` gives 30 keyframes including the target and `skipped 1`; `M = 80` gives evenly spaced indices whose gaps differ by at most 1. | node |
| PE-49 | Reduced motion. When `matchMedia('(prefers-reduced-motion: reduce)').matches` at the moment of navigation, the target is applied with no intermediate frame. `transition.active` may be `true` only while the target is being fetched, and `transition.progress` never takes a value strictly between 0 and 1. | Browser with reduced motion emulated: navigate from a reviewed entry to a neighbour 5 entries away. Sampled every frame, no bone snapshot differs from both the start pose and the target pose. On arrival the PE-18 label shows. | browser |
| PE-50 | Labels during a transition come from state through `provenanceFor` (ADR-0004), never set imperatively. Browser: sample `state.label` every frame during an adjacent hop: it is the transition tag from the first frame after navigation until arrival, then `ESTIMATED POSE`. | node + browser |
| PE-51 | Controls during a transition. The elbow and crouch sliders are `disabled` with the PE-20 note, and `#apply-estimate` is hidden. | PE-52 | Interruptible. A navigation during a transition retargets it from the **current interpolated pose**, with no jump. | PE-53 | Bounded rendering. | PE-56 | Cancellation. Reset, clear, avatar fallback and context failure end a transition in the same task. Reset and clear leave the rig at rest with estimate mode `'off'` (PE-16).
